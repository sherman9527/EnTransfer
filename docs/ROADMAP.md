## 1. 产品现状

- **稳**:文字型 PDF 全链路已跑通并防回归(R1–R24 + 54 不变式);图片(含 JPX)、表格、代码块处理有守卫;崩溃可断点续传;安装包精简(~120MB 不含模型);离线本地。

## 3. 未来 3 次迭代(建议锁定)

1. **#1 术语表**:配置 UI(设置页)+ 注入 prompt + 译后校验。验收:50 例术语命中 ≥ 95%,现有 R1–R24 全绿。
2. **#2 动态批并行**:token 预算组批。验收:同一 12 页样本总时延 -≥20%,批次完整性校验 0 丢段。
3. **#5 目录/书签 + #6 图片清晰度**:排版打磨。验收:输出含可点击 TOC,大图区不糊,安装包体积增幅 < 3MB。

## 4. 待跑实验(带 kill 判据)

- **E1 换/加模型 A/B**:候选 **Tencent Hy-MT / Hunyuan-MT**(有 1.8B 与 7B,GGUF 已存在)对打现主模型 Qwen3-1.7B。
  - 协议:`poc/models-bench` 跑 ≥50 例(技术书句),指标 = 人工评分 + 术语/数字保真 + tok/s + 内存 + GGUF 体积。
  - 先决:**核实许可可商用**(Tencent 系部分 Apache/自定义,逐模型看 LICENSE;拒 CC-BY-NC)。
  - kill:质量不升 or 速度/体积明显劣化 or 许可不可商用 → 不换。
- **E2 领域 LoRA**:在 `poc/lora-corpus` 上对 Hy-MT 或 Qwen3 微调技术书平行语料。
  - kill:自动对齐精度上限 ~50%(已知数据瓶颈),若加数据后 COMET/人工仍无 ≥ 一档提升 → 停。
- **E3 OCR 可行性 spike**:PP-OCRv5 ONNX(纯 ONNX,无 Python)在 20 页扫描样张的识别率 + 体积增量。
  - kill:识别率 < 90% 或安装包/内存代价破红线 → 不做,维持"拒扫描件"。
- **E4 量化对比**:同模型 Q4_K_M vs Q5/Q6 vs IQ 系列,质量-体积-速度三角。
  - kill:更小量化若质量掉一档不值。

## 5. 观察清单(以后再评估)

- **Hunyuan-MT-7B-GGUF**:7B 质量更高但 ~4GB,超出"精简 + 低配 CPU"目标;若 1.8B 版达标则优先小版。
- **Qwen3 更新的尺寸档 / 蒸馏版**:跟踪是否有更优 1–2B EN→ZH。
- **双语对照输出 / 分栏还原 / 批处理文件夹任务**:相邻功能,视需求排期。
- **词表记忆库(TM)/ 缓存跨书共享**:复用 translation-cache,降低重复段成本。
