# 踩坑复盘 2026-09 —— 反复栽的坑与应对（避免再犯）

这几轮（改名、模型选型、全面 code review、Delta Lake E2E 修复）里反复出现的
错误模式，及对应的硬性应对动作。按"最该记住"排序。

## 坑 1：只修眼前的那个症状，漏掉同一类的其它实例
**现象**：修代码块识别时，先加了 `%sql` magic-cell，又漏了控制台输出丢换行，
再漏了 JSON dump 被当表格，再漏了 `scala>` REPL 提示——四张截图各暴露一次，
其实是**同一个根因**（代码用了不透明子集字体 `g_d0_f1`，按内容符号猜代码不可靠）。
**根因**：看到 bug 就补那个 case，没先问"这是哪一类？同类还有几个实例？"
**应对**：修 bug 前先**归类**，找**根因信号**（这里是字体名，不是字号/内容符号）
一次覆盖整类。一个 case 修完，主动在同一文档里搜同类实例（如 grep 所有 `+---+`、
`%`、`>` 开头的段），别等用户再截图。

## 坑 2：改启发式阈值不跑对照测试 → 误伤正常样本
**现象**：为消除"prose 被当表格"加了 `填充率<0.45 丢弃` 的守卫，结果把 Manning
9 个**真表格**全杀了；换成"字号≤body×0.86 排除"同样误伤（表格单元格也是小字号）。
**根因**：只验证了"坏样本被修好"，没验证"好样本没被误伤"。
**应对**：任何放宽/收紧检测阈值的改动，**必须双向验证**——坏 case 修好 +
已知正例（Manning 真表格、正常段落）不变。改检测规则时先固定一个"金标准正例"
回归项。最终用**字体名精确匹配**（只排代码字体）才同时满足两边。

## 坑 3：拿单张截图当全部，不做完整体检
**现象**：用户连发 4 张截图，我一张张挤牙膏修；用户不得不"求求你完整的看一下"。
**应对**：收到"输出有问题"，先**全量体检**：渲染跨全书的代表性页（正文/代码/表格/
图/前后各几页）+ 全文分类统计（代码块数、表格数、未译率、页眉泄漏率），列出**所有**
gap 再一次性规划修复。工具已就位：`poc/gap-analysis/render-png` + `capture-audit`。

## 坑 4：验证跑在过期产物上 → 假结果
**现象**：esbuild bundle 没重编就验证，得到 "table:1" 的错误结论（其实是旧包）；
`git push ... | tail` 里管道吞掉真实退出码，一度误报成功/"Everything up-to-date"。
**应对**：
- 验证前确认 bundle 是当前源码重编的（看构建输出、必要时强制重编）。
- 判成败看**命令本身退出码**（`${PIPESTATUS[0]}`），别信管道尾部的 `tail`。
- push 后 `git fetch` 再核对 `origin/main..HEAD` 计数 = 0，才算真推上去。

## 坑 5：Windows 运行环境反复咬人
**现象**：Python 脚本 print 中文 → GBK 控制台 UnicodeEncodeError；缓存 rename
偶发 EPERM（R9 gate 反复红）；HF 缓存 symlink 不支持警告。
**应对**：脚本输出走 UTF-8 文件或设 `PYTHONIOENCODING=utf-8`；原子写 rename 加
EPERM/EBUSY 退避重试（已加进 translation-cache）；HF 下载设
`HF_ENDPOINT=hf-mirror` + `HF_HUB_DISABLE_XET=1`（新 hub 的 Xet 后端镜像不支持）。

## 坑 6：轻信报告/旧笔记，不自测
**现象**：旧笔记把"高性能Spark（影印版）"当成中英对照对（其实是英文影印，且是扫描
图无文字层）；这次也差点假设"opus-mt 600M 专用翻译器应该更好"。
**应对**：一切自测说话（AGENTS.md 已有此条）。实测 opus-mt 退化重复、NanoJev 是
迷宫/贪吃蛇决策模型——都是**一手验证**才纠正的直觉误判。

## 坑 7：改了结构不变式，没同步 verify 守卫
**现象**：CAPTURE_VERSION 改了、新增 line-utils/代码字体判定，但没在 verify-build.js
加对应结构不变式检查。
**应对**：每个"结构/时序不变式"修复，同步加一条 verify 检查（如 CAPTURE_VERSION 值、
detectTables 排除代码字体、joinFragments 存在）。

## 值得固化的正确做法（继续用）
- **TDD 红测先行**：R17–R20 把断词/页眉/剥页码的坑固化成回归，改坏立刻红。
- **一手资料优先**：模型能力查它自己的 README/manifest，不靠记忆或二手报告。
- **对照样本**：改任何检测启发式，Manning（真表格）+ Delta（代码海）双书互测。
- **量化再采纳**：opus-mt/NanoJev 都用数据判"不采纳"，不凭"看起来新/小/专用"。

## 一句话总结
> 这几轮最大的教训不是"bug 多"，而是**我在用点状思维修系统性问题**：
> 找根因信号（而非表症）、双向验证（而非只修坏例）、先全量体检（而非挤牙膏）、
> 确认产物新鲜（而非信过期结果）。把这四条固化进流程，同类返工可基本消除。
